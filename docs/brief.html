The challenge

Solo, free, online. Find one gap in a field you know well, where frontier AI models fail but an expert succeeds, and turn it into an eval: tasks plus a reliable grader. It is not a build-an-agent contest and not model training. You choose the domain. Recommended 5 to 10 well-designed tasks; quality over quantity. Single-turn or agentic both welcome.

Judging rubric (100 points)

CriterionPtsAsk yourself
Task design20Would two experts reach the same verdict? Each task has a reference solution; everything graded is stated in the task.
Grader reliability20Accepts every reference solution, rejects deliberately wrong answers. Any LLM judge uses specific rubric items and is checked against expert grading.
Real-world relevance15Would a practitioner care? README says who relies on this work and what failure costs.
Evidence of model limitations15Frontier models, several trials per task, a spread across models, transcripts backing each failure explanation.
Reproducibility15A judge runs it from a clean environment using only the README: commands, versions, data, runtime, cost.
Human expertise and review10You checked every task, answer and grading rule. README says how AI tools were used and reviewed. No generic tasks or filler.
Insight / hot take5A clear, unexpected lesson about where AI falls short.

Scoring only happens after eligibility, completeness, integrity and reproducibility checks pass.

README must contain

  1. Short description
  2. Video walkthrough link
  3. Domain and expertise
  4. What it tests and why it matters (who it is for)
  5. Setup and run instructions: clean environment, one command where possible, how to supply API keys, runtime and cost
  6. Models tested and results: exact model IDs or versions, run date, settings (temperature, trials per task), scores
  7. Failure analysis: where and why models fail
  8. Prior work and sources: anything that existed before, any benchmarks or datasets used

The guide also suggests: task overview, how you validated the grader, representative transcripts, main failure mode and hot take, and an "AI use" section.

Also required inside the ZIP

  • Tasks: inputs and expected outputs or grading criteria, including edge cases and judgment calls.
  • Scoring logic: automated grading, a rubric, or both, with how scores are calculated. An AI grader must be named, with its prompt and a reliability check.
  • Results: raw model outputs and scores from your own run.
  • Dependencies: a requirements file plus .env.example (key names only).
Do not include: videos or large datasets (host and link them), confidential employer or client data, private personal information, third-party material you cannot share, API keys or passwords.

What makes a strong eval (guide)

  • Realistic professional tasks, not trick questions, riddles or letter counting. You can explain why it is hard before running any model.
  • Grade the outcome, not the steps. Prefer code-based graders (exact match, numeric tolerance, regex, schema, unit tests). Use partial credit for multi-part answers.
  • Run 3 to 5 trials per task. Report pass@k and pass^k (consistency), and the spread.
  • Sanity checks: 0% everywhere usually means a broken task or grader; a small model beating a frontier model means look for ambiguity; if the best model scores about 100%, there is no headroom.
  • Keep reference answers away from the model. Make sure an output cannot pass by accident.
  • Read the transcripts, especially failures. Did the model err, or did your grader reject a valid answer?
  • Do not pick tasks only because one model failed them. Pick what an expert judges hard, then confirm with models.

Pre-submission checklist (guide)

  • Every task has a reference solution that passes its grader
  • Deliberately wrong answers fail the grader
  • Everything the grader checks is stated in the task
  • At least one frontier model tested, multiple trials per task
  • You read the failing transcripts and can explain why models fail
  • README explains how to run, with versions, cost and runtime
  • ZIP opens, under 50 MB, no videos, no keys or private data
  • Prior work disclosed; representative transcripts included for each reported model
  • Video link opens without permission and has audio; description filled in
  • You scored your own project against the rubric and reviewed every task, answer and rule yourself

Skills and tools

This is eval design, not model training. Heavy ML skills matter only if your domain needs them. No API credits are provided.
  • Core skills: task design, grader design, dataset hygiene (JSONL/CSV, no leakage), reproducibility (pinned deps, temperature 0, one-command run), clear writing.
  • Tools: Python 3 with venv or uv, pytest, pandas or polars if needed, an OpenAI-compatible client pointed at OpenRouter. Optional: Inspect AI or Harbor (the guide says neither is required). These are my suggestions from general knowledge, not verified.
  • Community Claude Code skills (unvetted, read the SKILL.md first): ml-model-training, pytorch, ml-expert.
  • Further reading (from the guide): Demystifying evals for AI agents, Automating eval design and hillclimbing with Claude.
